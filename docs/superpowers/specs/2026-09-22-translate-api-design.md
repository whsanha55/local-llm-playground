# 파일 번역 API (`POST /translate`) 설계

날짜: 2026-09-22
상태: 승인됨

## 배경

gemma4_api.py(MLX 로컬 LLM 서버)에 파일 업로드 → 한국어 번역 기능 추가.
주 사용처: 자막(SRT) 번역. 일반 텍스트(txt)도 지원.

## 요구사항 (확정)

- 입력: `.srt`, `.txt` 파일 업로드 (multipart)
- SRT는 블록 번호·타임스탬프 구조 100% 유지, 텍스트만 번역
- 완결 동기 응답 (스트리밍 아님)
- chunk 병렬 처리: 스레드 풀, 모델 1개 공유
- 웹 UI(gemma4_ui.html)에 업로드/결과 기능 추가
- 프롬프트는 범용 (특정 태그·형식에 대한 특수 지시 없음)

## API 명세

`POST /translate` — multipart/form-data

| 필드 | 설명 |
|---|---|
| `file` | .srt 또는 .txt |

응답:

```json
{
  "translation": "번역된 전체 텍스트",
  "blocks": 1405,
  "chunks": 20,
  "seconds": 623.4,
  "model": "supergemma-abliterated"
}
```

- 파일 2MB 초과 → 413
- 지원 안 하는 확장자 → 400

## SRT 파싱·청킹·재조립

1. **파싱**: 빈 줄 기준 블록 분리 → (번호, 타임스탬프 라인, 텍스트 라인들). 타임스탬프는 ` --> ` 포함 라인으로 식별.
2. **청킹**: 블록 경계에서만 분할, 청크당 목표 4,000자. 블록 수십 개씩 묶음.
3. **번역**: 청크 내 블록 텍스트를 `[번호] 텍스트` 한 줄 형식으로 프롬프트에 넣고, 응답도 같은 형식으로 요청. **타임스탬프·블록번호는 모델에 전송하지 않음** → 구조 보존이 서버 책임이 되어 100% 보장.
4. **재조립**: 원본 번호·타임스탬프 + 파싱된 번역 텍스트로 SRT 재생성. `\n\n` 블록 구분.

마커 파싱 실패(블록 수 불일치) 시 해당 청크 1회 재시도(순차), 재실패 시 500 + 청크 인덱스 안내.

## txt 처리

문단(`\n\n`) 경로 분할 → 청크 목표 4,000자 → 동일 파이프라인 → 결과 join. SRT 재조립 없음.

## 프롬프트 (범용)

```
아래 [번호]로 시작하는 자막/텍스트 줄들을 한국어로 자연스럽게 번역해줘.
번역문만 [번호] 접두와 함께 한 줄씩 반환하고, 다른 설명은 하지 마.

[1] ...
[2] ...
```

max_tokens: `min(4096, max(1024, 청크 글자수))`. enable_thinking=False 고정.

## 병렬 처리

- `ThreadPoolExecutor(max_workers=TRANSLATE_WORKERS 환경변수, 기본 3)`
- 각 워커: `build_prompt` → `generate()` (모델 가중치 공유, KV 캐시는 호출별 생성)
- MLX는 GIL 해제 + 스레드별 Metal 스트림 → 청크 N 디코드 중 청크 N+1 프롬프트 평가 겹침 (실측 통상 1.3~1.6배)
- **스파이크 테스트 선행**: 구현 첫 단계로 2스레드 동시 `generate()` 검증. 실패 판정 시 `max_workers=1` 폴백 (코드 경로 동일, 설정만 차이)

## 인코딩

`utf-8-sig` → `cp949` 순 폴백 디코딩. 윈도우 생성 파일 대비.

## 웹 UI

gemma4_ui.html에 추가:

- 파일 선택 + 번역 버튼
- 요청 중 스피너 + 경과 시간 표시 (동기 요청, 파일 규모상 수 분 소요)
- 결과 표시창 + `.srt` 다운로드 버튼 (원본 확장자 유지)

## 코드 구조·테스트

- 기존 단일 파일 패턴 유지: 파서/청커/마커 재조립을 gemma4_api.py 내 순수 함수로 분리
- assert 기반 self-check (`python -m gemma4_api`): 파싱→청킹→재조립 왕복이 원본 구조와 일치하는지
- 스파이크: 병렬 generate 스레드 안전성 + 대략적 속도 배수 측정
- 실제 검증: srt-sample/The_Odyssey.srt (1,405블록, 90KB)로 종단 테스트

## 예상 소요

Odyssey 샘플 기준 약 10~15분 (출력 약 2만 토큰, 로컬 e4b 추론). UI fetch는 타임아웃 없음, curl은 `--max-time` 필요.
